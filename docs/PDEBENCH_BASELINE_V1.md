# PDEBench 朴素基线核对 V1（2026-10-16，D6）

> README 记录的硬伤之一："基线在 PDEBench 上连空间均值基线都没打过"。
> 本轮把它量化，结论是：**该问题被精确定位到 DeepONet，FNO 不受影响**。

## 1. 两个朴素基线（不训练）

| 基线 | 定义 | test mean relative L2 |
|---|---|---:|
| B1 mean-field | 预测 = 训练集目标场的**逐点平均**（常数场） | 0.9994 |
| B2 input-mean | 预测 = 每个样本**输入场的均值**（常数场） | **0.3758** |

B2 不是随便凑的：PDEBench 的 1D Burgers 是周期边界、无源项，
∫u dx 守恒，因此"解的均值 ≈ 初值均值"是一个**物理上成立的免费预测**。
一个模型若打不过 B2，说明它连这条守恒律都没学到，任何关于其
"表示/优化瓶颈"的讨论都缺乏说服力。

（B1 ≈ 1.0 说明目标场在逐点上高度异质，"平均场"毫无预测力，只作参照。）

## 2. 结果（3 seed，PDEBench Burgers Nu=0.001，fixed t1，1000/200/200）

| 配置 | seed 0 | seed 1 | seed 2 | 相对 B2 (0.3758) |
|---|---:|---:|---:|---|
| `deeponet_fourier` @6000 | 0.4165 | 0.4024 | 0.4176 | **WORSE**（−7% ~ −11%） |
| `deeponet_mlp` @6000 | 0.3872 | 0.3728 | 0.3876 | 边缘（−3.0% ~ +0.8%） |
| `fno_w32_m16` @1500 | 0.2218 | 0.2160 | 0.2241 | **BETTER**（+40% ~ +43%） |
| `fno_w32_m16` @6000 | 0.2150 | 0.2049 | 0.2193 | **BETTER**（+42% ~ +46%） |
| `fno_w64_m32` @6000 | 0.2204 | 0.2189 | 0.2276 | **BETTER**（+39% ~ +42%） |

## 3. 结论

1. **FNO 明确打过守恒律基线**（约 +40%），且 3 个 seed 一致。
   ⇒ README 那条硬伤在 FNO 上**不成立**，可以据此更新对外表述。
2. **DeepONet 打不过**：即使把步数从 1500 加到 6000（FNO 的 4 倍预算），
   Fourier trunk 仍比 B2 **差 7%~11%**；MLP trunk 在边缘（一个 seed 好 0.8%，
   两个 seed 差 3%）。
   ⇒ 硬伤被定位成：**不是"我们的方法弱"，而是"DeepONet 这条线在这份公开数据上
   连守恒律给出的免费常数预测都不如"**。
3. **加容量/加步数对 FNO 几乎无效**（0.2218 → 0.2204，噪声量级）。
   这与 `READOUT_ATTRIBUTION_V1.md` 的 D1 结论一致：FNO 的
   `opt_gap/train_rel` 只有 0.037，训练误差已贴在 readout 地板上，
   所以单纯加预算不解决问题——FNO 卡在表示与泛化，不在优化。
4. **DeepONet 加步数确实有改善**（0.3936 → 0.387/0.402 量级），
   但幅度不足以跨过 B2，与 D1 判定它"优化受限"一致：它还有优化空间，
   只是这份空间不足以救活它。

## 4. 对投稿策略的直接影响

- 论文里**不要把 DeepONet 当作"我们的方法"的基线**来比；
  更合适的定位是：DeepONet 是**被诊断的对象**，
  而 FNO 是"同一个诊断框架下表现正常的对照"。
- 对外表述应改为："在 PDEBench 1D Burgers 上，我们的 FNO 基线相对
  守恒律朴素基线有约 40% 的余量；同设置下 DeepONet 反而低于该基线，
  这一事实本身也是本文诊断结论的一部分。"

## 5. 局限（必须一起读）

1. 只有 **1 个 PDE、1 个粘度（Nu=0.001）、1 个目标时刻、1 个分辨率**。
2. B2 依赖 Burgers 的质量守恒；对非守恒 PDE（如带源项的扩散-反应）
   该基线不成立，需要另设朴素基线（例如"上一时刻的场"或"线性外推"）。
3. 步数只到 6000；未做 20k/50k（README 记录 1D 在 6k→20k→50k 仍单调改善，
   因此 DeepONet 在更大预算下**有可能**跨过 B2 —— 这是下一步必须补的，
   否则"DeepONet 打不过基线"会被预算不足所混淆）。
4. 未做学习率/权重衰减的调优，也未做 FNO 的 modes/层数系统扫描。
